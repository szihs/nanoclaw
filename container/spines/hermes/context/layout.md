### Hermes repository layout

Two copies of the same tree: the **release** at `/workspace/extra/hermes-release` (read-only, at the pinned tag recorded in `/workspace/extra/hermes-release/RELEASE_MANIFEST.json`, fallback: the spine's `vars.release_tag` in `coworker-types.yaml` — cite from here) and the **fork** at `/workspace/agent/hermes-agent` (rw — build here, one worktree per target at `/workspace/agent/wt-<target-slug>`). Paths below are relative to either root.
When a report, ADR, or review names the release, cite the `tag` and `commit` fields from `RELEASE_MANIFEST.json` (written by the operator's `scripts/hermes-pin.sh`), not a remembered version string.

- `run_agent.py` — `AIAgent`: synchronous core conversation loop, tool dispatch, budget/interrupt, session persistence (~12k LOC). Core — plugins never edit it.
- `model_tools.py` — tool orchestration; importing it is the ONLY implicit trigger of `discover_plugins()` (`AGENTS.md:794-798`). `toolsets.py` — `TOOLSETS` + `_HERMES_CORE_TOOLS`; a tool reaches the model only if a toolset names it.
- `cli.py`, `hermes_cli/` — the `hermes` CLI (`hermes_cli/main.py:main`), setup wizard, `config.py` (`DEFAULT_CONFIG`, `OPTIONAL_ENV_VARS`), and the plugin system: `plugins.py` (`PluginManager`, `PluginContext`, `VALID_HOOKS`), `plugin_dev.py` (doctor), `plugins_cmd.py` + `subcommands/plugins.py` (plugin CLI), `agent_plugins.py` (Agent Plugins v1), `plugin_capabilities.py`, `middleware.py`, `curses_ui.py` (all menu pickers).
- `hermes_constants.py`, `hermes_logging.py` — `get_hermes_home()`, `display_hermes_home()`, profile-aware logs.
- `agent/` — prompt_builder, context_compressor, auxiliary_client, memory_manager + `MemoryProvider` ABC, `shell_hooks.py` (Claude-Code-compatible shell-hook bridge: `hooks:` in config.yaml, `{"decision":"block"}` / exit 2), outbound_webhooks, curator, display.
- `tools/` — self-registering core tools (`registry.register` at import), `approval.py` (dangerous-command gate), `terminal_tool.py`, `delegate_tool.py`, `environments/` (local, docker, ssh, singularity, modal, daytona, vercel_sandbox backends).
- `gateway/` — `run.py` `GatewayRunner`, `session.py`, `platforms/base.py` `BasePlatformAdapter`, `authz_mixin.py`, `status.py`, `builtin_hooks/`.
- `plugins/` — bundled plugins, the reference for everything you build: `platforms/{a2a,discord,slack,telegram,irc,matrix,teams,whatsapp,…}` (`kind: platform`), `memory/` (closed set, bundled-first discovery), `model-providers/`, `context_engine/`, `image_gen/`, `kanban/`, `observability/`, `disk-cleanup/`, plus `plugin_storage.py` (`plugin_data_dir` / `plugin_db`) and `plugin_utils.py` (`lazy_singleton`).
- `skills/`, `optional-skills/` — bundled SKILL.md skills by category. `cron/` — `jobs.py` + `scheduler.py`. `tui_gateway/` — JSON-RPC backend behind `hermes --tui`, the desktop app, and headless `hermes serve`. `acp_adapter/` — ACP server for editors.
- `ui-tui/` (Ink/React TUI), `apps/desktop/` + `apps/shared/` (Electron desktop; own `AGENTS.md`), `web/` (dashboard) — TypeScript; their tests run in vitest/npm, not pytest.
- `tests/` — pytest suite: ~3.5k test files / ~37k test functions (126 s on CI's 96 cores; expect far longer here). `conftest.py` sandboxes `HERMES_HOME`, scrubs credentials, sets `HERMES_DISABLE_LAZY_INSTALLS=1`, resets the plugin singleton. Plugin-system tests: `tests/hermes_cli/test_plugin*.py`, `test_agent_plugins.py`, fixtures in `tests/hermes_cli/fixtures/plugin_compat_legacy/`; bundled-plugin tests: `tests/plugins/`; skills: `tests/skills/test_<skill>_skill.py`. See `/hermes-build` to set up and run.
- `scripts/` — `run_tests.sh` (the only sanctioned test runner), `run_tests_parallel.py`, `check-windows-footguns.py`, `install.sh`, `ci/classify_changes.py`.
- `website/docs/` — Docusaurus docs: `developer-guide/plugins/index.md` is the plugin contract, `developer-guide/*-plugin.md` one per registration kind, `user-guide/profile-distributions.md`, `user-guide/features/hooks.md`. `docs/` — internal design notes and ADRs (`docs/ADR.md` — dated `## YYYY-MM-DD: <title>` entries; `docs/rfcs/`, `docs/security/`, `docs/middleware/`, `docs/design/`, `docs/kanban/`, `docs/observability/`).
- `AGENTS.md`, `CONTRIBUTING.md`, `apps/desktop/AGENTS.md` — the maintainers' rules; read the relevant section before proposing anything.
- `.github/workflows/` — `ci.yaml` orchestrator → `tests.yml` (`scripts/run_tests.sh`, 96 cores, 30 min), `lint.yml` (blocking `ruff check .`), `tests-os.yml`, `js-tests.yml`, `uv-lockfile-check.yml`, `supply-chain-audit.yml`, `docker.yml`. CI or lint questions → `/hermes-plan` (mode: investigate), logs via `/hermes-github`.
- `Dockerfile` — the official image's apt set (line 73) is the reference for what a Hermes runtime expects on the box.
